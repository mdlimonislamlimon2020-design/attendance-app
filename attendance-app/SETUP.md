## ১. অ্যাপে যা যা আছে

### স্টুডেন্ট (`/signup`, `/login`)
ফোন নম্বর ও পাসওয়ার্ড দিয়ে সাইনআপ/লগইন করেন (রেজিস্ট্রেশন নম্বর দিয়ে যাচাইয়ের পর)।
সাইনআপের সময় ইমেইল, রক্তের গ্রুপ এবং অভিভাবকের ফোন নম্বরও নেওয়া হয় (জরুরি প্রয়োজনে
যোগাযোগের জন্য) — এই তথ্যগুলো ফোন নম্বরের মতোই শুধুমাত্র অ্যাডমিন দেখতে পারেন।

ড্যাশবোর্ডে যা দেখা যায়:
- মোট ক্লাস, নিজের উপস্থিতি, শিক্ষক-ভিত্তিক ব্রেকডাউন (তারিখ-ভিত্তিক বিস্তারিত তালিকাসহ)
- একটি মাস-নির্বাচক — নির্দিষ্ট মাসের হিসাব অথবা পুরো সেশনের মোট হিসাব দেখা যায়
- উপস্থিতির লিডারবোর্ড
- নোটিশ বোর্ড (তালিকায় ট্যাপ করলে বিস্তারিত খোলে)
- ইনকোর্স পরীক্ষার প্রকাশিত ফলাফল (নিজেরটা শুধু, ক্লাসমেটদেরটা না)
- ছুটির তালিকা
- উপস্থিতি ৭৫%-এর নিচে নামলে স্বয়ংক্রিয় সতর্কতা
- নিজে পাসওয়ার্ড পরিবর্তনের সুবিধা

### CR (ক্লাস রিপ্রেজেন্টেটিভ)
স্টুডেন্টের সব সুবিধার সাথে বাড়তি একটি "নতুন নোটিশ দিন" ফর্ম — শুধু নিজের সেশনের জন্য।

### শিক্ষক (`/teacher/login`)
অ্যাডমিন প্রতিটি শিক্ষকের জন্য ফোন নম্বর ও পাসওয়ার্ড সেট করে দেন। এরপর শিক্ষক নিজে
লগইন করে নিজের ড্যাশবোর্ড থেকে:
- এক ক্লিকে রোল কল নিতে পারেন (তারিখ বেছে "রোল কল নিন" চাপলেই পুরো স্টুডেন্ট তালিকা
  চেকলিস্ট আকারে চলে আসে)
- নিজের নেওয়া ক্লাসের হাজিরা এডিট করতে পারেন (অন্য কারো ক্লাসে হাত দিতে পারেন না —
  এটা শুধু UI-এর নিয়ন্ত্রণ না, সরাসরি Firebase Rules দিয়ে বলবৎ করা)
- নিজের সাবজেক্টের ইনকোর্স পরীক্ষা তৈরি ও ফলাফল প্রকাশ করতে পারেন
- ছুটির তালিকা দেখতে পারেন

> ক্লাস ডিলিট করা এখনো admin-only — শিক্ষক ভুল ক্লাস তৈরি করলে অ্যাডমিনকে ডিলিট
> করতে বলতে হবে, তবে হাজিরা নিজেই এডিট করে ঠিক করতে পারবেন।
>
> একই শিক্ষক একাধিক সেশনে ক্লাস নিলে প্রতিটি সেশনের জন্য আলাদা শিক্ষক-রেকর্ড ও আলাদা
> লগইন লাগবে — পুরো অ্যাপটাই সেশন-ভিত্তিক আলাদা রাখা হয়েছে বলে এই সীমাবদ্ধতা।

### অ্যাডমিন (`/admin/login`)

| ট্যাব | কাজ |
|---|---|
| সেশন | তৈরি, এডিট, আর্কাইভ, ডিলিট (ডিলিটে সব ডাটা একসাথে মুছে যায় — নিশ্চিত করতে সেশনের নাম টাইপ করতে হয়) |
| স্টুডেন্ট | রোস্টার ইমপোর্ট, সার্চ, নাম এডিট, বাদ দেওয়া, সাইনআপ রিসেট, CR বানানো/সরানো, সাম্প্রতিক সাইনআপ মনিটরিং |
| শিক্ষক | যোগ, রিনেম, মুছে ফেলা, লগইন সেট/রিসেট |

| ফলাফল | ইনকোর্স পরীক্ষা তৈরি, নম্বর এন্ট্রি, ফলাফল প্রকাশ |
| নোটিশ | পোস্ট/ডিলিট |
| রিপোর্ট | মাস অনুযায়ী ফিল্টার করে CSV এক্সপোর্ট, কম-উপস্থিতির তালিকা |
| ছুটির তালিকা | প্রতিষ্ঠান-ওয়াইড ছুটি যোগ করা |

পাওয়া যায় (**এতে ফোন নম্বর থাকে, তাই এই ফাইল কারো সাথে শেয়ার করবেন না**)।

## ২. Firebase প্রজেক্ট তৈরি

1. https://console.firebase.google.com খুলুন → **Add project** → একটি নাম দিন
   (যেমন: `titumir-attendance`)।
2. বাম মেনু থেকে **Build > Authentication** → **Get started** → **Sign-in method**
   ট্যাবে **Email/Password** চালু করুন।
3. **Build > Realtime Database** → **Create Database** → লোকেশন বেছে নিন (Singapore
   কাছাকাছি ভালো) → শুরুতে "locked mode"-এ রাখুন, rules একটু পরে বসানো হবে।
4. **Project settings (⚙️ আইকন) > General** ট্যাবে নিচে "Your apps" সেকশনে Web app
   (`</>`) যোগ করুন → দেখানো `firebaseConfig` অবজেক্টটা কপি করে রাখুন।

## ৩. কনফিগ বসানো

`src/firebase.ts` ফাইল খুলুন এবং তাতে থাকা `firebaseConfig` অবজেক্টের মানগুলো
আগের ধাপে কপি করা মান দিয়ে প্রতিস্থাপন করুন।

## ৪. Security Rules পাবলিশ করা

1. Firebase Console → **Realtime Database** → **Rules** ট্যাবে যান।
2. এই প্রজেক্টের `database.rules.json` ফাইলের পুরো কনটেন্ট কপি করে পেস্ট করুন।
3. **Publish** বাটনে ক্লিক করুন।

> **কেন এটা গুরুত্বপূর্ণ:** Rules ছাড়া অ্যাপ চালু হলেও কোনো ডাটা পড়া/লেখা যাবে না
> (সব জায়গায় "Permission denied" এরর আসবে)। কোডে যতবার পরিবর্তন হবে যদি তাতে নতুন
> ডাটাবেজ নোড যুক্ত হয়, ততবার এই ধাপটা আবার করতে হবে — নতুন `database.rules.json`
> পেলে সেটা আবার Publish করে দিন।
>
> ফোন নম্বর, ইমেইল, রক্তের গ্রুপ, অভিভাবকের ফোন — এসব `studentsPrivate` নামে আলাদা
> জায়গায় থাকে, যেটা শুধু অ্যাডমিন পড়তে পারেন। `students` নোডে শুধু নাম, রেজিস্ট্রেশন
> নম্বর, CR স্ট্যাটাস থাকে — এগুলো লিডারবোর্ডের জন্য সবাইকে দেখাতে হয় বলে উন্মুক্ত রাখা।

## ৫. প্রথম অ্যাডমিন অ্যাকাউন্ট তৈরি

1. Firebase Console → **Authentication** → **Users** ট্যাবে → **Add user** → নিজের
   ইমেইল ও একটি পাসওয়ার্ড দিন।
2. তৈরি হওয়া ইউজারের **UID** কপি করুন।
3. **Realtime Database** → **Data** ট্যাবে গিয়ে ম্যানুয়ালি নিচের এন্ট্রিটা যোগ করুন:
   ```
   admins/<UID> = true
   ```
4. এখন `/admin/login` পেজে ওই ইমেইল ও পাসওয়ার্ড দিয়ে লগইন করা যাবে।

## ৬. রান করা ও ডেপ্লয় করা

স্থানীয় কম্পিউটারে চালানো:
```bash
cd attendance-app
npm install     # লোকাল ডেভেলপমেন্ট সার্ভার
npm run dev     # প্রোডাকশন বিল্ড (dist/ ফোল্ডারে তৈরি হবে)
```

Firebase Hosting-এ ডেপ্লয় করা (সবচেয়ে সহজ পথ):
```bash
npm install -g firebase-tools
firebase login
firebase init hosting   # public directory: dist, single-page app: yes
npm run build
firebase deploy --only hosting
```

## ৭. প্রথমবার ব্যবহারের ধাপ

1. `/admin/login`-এ লগইন করুন।
2. **সেশন** ট্যাবে একটি সেশন তৈরি করুন (যেমন: "H3 (২১-২২)")।
3. **স্টুডেন্ট** ট্যাবে "H3 (২১-২২) রোস্টার বসান" বাটনে ক্লিক করুন — ২০৪ জন স্টুডেন্ট
   একসাথে যোগ হয়ে যাবে। (অন্য সেশনের জন্য পাশের বক্সে পেস্ট করে ইমপোর্ট করা যায় —
   ফরম্যাট: `SL REG NAME`, প্রতি লাইনে একজন।)
4. **শিক্ষক** ট্যাবে যেসব শিক্ষক ক্লাস নেন তাদের নাম যোগ করুন। যাদের নিজে লগইন করে
   রোল কল নিতে হবে, তাদের নামের নিচে "লগইন সেট করুন" চেপে ফোন নম্বর ও পাসওয়ার্ড দিন —
   এরপর তারা `/teacher/login`-এ গিয়ে নিজে ঢুকতে পারবেন।
5. ক্লাস হওয়ার পর হয় **অ্যাডমিন নিজে** "ক্লাস ও হাজিরা" ট্যাব থেকে, অথবা **শিক্ষক নিজে**
   তার ড্যাশবোর্ড থেকে — তারিখ বেছে ক্লাস তৈরি করলেই হাজিরার চেকলিস্ট চলে আসবে।
6. স্টুডেন্টরা নিজেরা `/signup`-এ গিয়ে রেজিস্ট্রেশন নম্বর দিয়ে যাচাই করে ফোন+পাসওয়ার্ড
   সেট করে অ্যাকাউন্ট খুলবেন।
7. যাকে CR বানাতে চান, **স্টুডেন্ট** ট্যাবে তার পাশে "CR করুন" বাটনে ক্লিক করুন।
8. **ছুটির তালিকা** ট্যাবে সরকারি ছুটি, ঈদের ছুটি ইত্যাদি যোগ করে রাখলে সব স্টুডেন্ট ও
   শিক্ষকের ড্যাশবোর্ডে দেখা যাবে।
9. **ফলাফল** ট্যাবে ইনকোর্স পরীক্ষা তৈরি করে নম্বর দিন, তারপর প্রকাশ করুন।

## ৮. পাসওয়ার্ড ভুলে গেলে

**লগইন করা অবস্থায় নিজে বদলাতে চাইলে:** ড্যাশবোর্ডের উপরে "পাসওয়ার্ড পরিবর্তন করুন"
লিংক থেকে বর্তমান পাসওয়ার্ড দিয়ে নতুন পাসওয়ার্ড সেট করা যায় (স্টুডেন্ট ও শিক্ষক দুজনের
জন্যই আছে)।

**পুরোপুরি লগইন করতে না পারলে (আসল "ভুলে গেছি" সমস্যা):** এখানে একটা প্রযুক্তিগত
সীমাবদ্ধতা আছে — কোনো ব্যাকএন্ড সার্ভার ছাড়া অ্যাডমিনও অন্য কারো পাসওয়ার্ড সরাসরি
বদলে দিতে পারেন না। তাই সমাধান হলো "রিসেট":

1. অ্যাডমিন প্যানেলে (স্টুডেন্টের জন্য "স্টুডেন্ট" ট্যাব, শিক্ষকের জন্য "শিক্ষক" ট্যাব)
   সংশ্লিষ্ট ব্যক্তির পাশে "রিসেট" বাটনে ক্লিক করুন।
2. এতে তার পুরোনো লগইন তথ্য মুছে যাবে। সে আবার সাইনআপ/লগইন-সেট করে **নতুন ফোন নম্বর ও
   নতুন পাসওয়ার্ড** সেট করতে পারবে — এটা তাৎক্ষণিকভাবেই কাজ করবে।
3. ঠিক **আগের ফোন নম্বরটাই** আবার ব্যবহার করতে চাইলে, তার আগে Firebase Console →
   Authentication → Users-এ গিয়ে ওই নম্বর-ভিত্তিক পুরোনো অ্যাকাউন্টটা ম্যানুয়ালি ডিলিট
   করে দিতে হবে (নাহলে "এই নম্বর দিয়ে আগেই অ্যাকাউন্ট আছে" এরর আসবে)।

## ৯. অভিভাবকের কাছে SMS পাঠানো (ঐচ্ছিক)

এই ফিচারটা "শুধু rules Publish করুন" দিয়ে হবে না — এখানে তিনটা নতুন জিনিস লাগবে:
Firebase-এর Blaze প্ল্যান, একটি SMS গেটওয়ে অ্যাকাউন্ট, আর Firebase CLI দিয়ে একটি
Cloud Function ডিপ্লয়। **প্রতিটি SMS-এর জন্য টাকা কাটবে** (আনুমানিক ০.৩ টাকা/SMS,
গেটওয়ে ভেদে কমবেশি হতে পারে) — এটা একবারের খরচ না, প্রতি মাসে যত ব্যবহার করবেন
ততই খরচ হবে।

### ৯.১ Firebase Blaze প্ল্যান চালু করা
Firebase Console → বাম নিচে "Upgrade" অথবা Project Settings → Usage and billing →
Blaze প্ল্যানে আপগ্রেড করুন (একটি ব্যাংক কার্ড লাগবে)। এই স্কেলে Cloud Function-এর
নিজের খরচ সাধারণত ফ্রি-টায়ারের মধ্যেই থাকে — আসল খরচ SMS গেটওয়ের।

### ৯.২ একটি SMS গেটওয়ে অ্যাকাউন্ট খোলা
এই কোড **BulkSMSBD.net**-এর জন্য লেখা (বাংলাদেশের একটি জনপ্রিয় গেটওয়ে, প্রতি SMS
প্রায় ০.২৫–০.৩৪ টাকা)। অ্যাকাউন্ট খুলে:
- **API Key** সংগ্রহ করুন (ড্যাশবোর্ডে পাওয়া যাবে)
- একটি **Sender ID**-এর জন্য আবেদন করুন ও অনুমোদনের অপেক্ষা করুন (কিছুদিন লাগতে পারে)
- অ্যাকাউন্টে টাকা রিচার্জ করুন
- ড্যাশবোর্ডে "IP White List" অপশনটা বন্ধ করে দিন (নাহলে Cloud Function থেকে কল
  ব্লক হবে)

অন্য কোনো গেটওয়ে ব্যবহার করতে চাইলে শুধু `functions/index.js`-এর `sendBulkSms`
অংশটা বদলালেই হবে — বাকি সব কোড অপরিবর্তিত থাকবে।

### ৯.৩ Firebase CLI ইনস্টল ও প্রজেক্ট কানেক্ট করা
```bash
npm install -g firebase-tools
firebase login
cd attendance-app
firebase use --add     # আপনার titumir-attendance প্রজেক্ট বেছে নিন
```

### ৯.৪ গোপন তথ্য (secrets) সেট করা
API key ও Sender ID কোডে না লিখে Firebase-এর secret ম্যানেজারে রাখা হয়:
```bash
firebase functions:secrets:set BULKSMSBD_API_KEY
firebase functions:secrets:set BULKSMSBD_SENDER_ID
```
প্রতিটির জন্য টার্মিনালে প্রম্পট আসবে, মান পেস্ট করে এন্টার দিন।

### ৯.৫ ডিপ্লয় করা
```bash
cd functions
npm install
cd ..
firebase deploy --only functions
```
প্রথমবার ডিপ্লয়ে কয়েক মিনিট লাগতে পারে। শেষ হলে Firebase Console → Functions-এ
`sendDailyAttendanceSms` ও `publishExamResults` দেখা যাবে।

### ৯.৬ ব্যবহার
- **দৈনিক হাজিরার SMS**: অ্যাডমিন প্যানেলের "ক্লাস ও হাজিরা" ট্যাবে তারিখ দিয়ে
  "SMS পাঠান" চাপলেই সেদিনের ক্লাসের ভিত্তিতে প্রতিটি স্টুডেন্টের অভিভাবককে আলাদা
  SMS চলে যাবে (যাদের অভিভাবকের নম্বর নেই, তারা বাদ পড়বে)।
- **ইনকোর্স ফলাফলের SMS**: "ফলাফল" ট্যাবে পরীক্ষা তৈরি করে নম্বর বসানোর পর "ফলাফল
  প্রকাশ করুন" চাপলে — যাদের নম্বর দেওয়া আছে তাদের প্রত্যেকের অভিভাবকের কাছে
  ("আপনার সন্তান X নম্বর পেয়েছে Y-এর মধ্যে") SMS চলে যাবে, আর স্টুডেন্টরা নিজেদের
  ড্যাশবোর্ডে ফলাফল দেখতে পারবেন।

> **একজন স্টুডেন্ট শুধু নিজের নম্বরই দেখতে পারবেন, ক্লাসমেটদেরটা না** — উপস্থিতির
> লিডারবোর্ডের মতো প্রকাশ্য রাখা হয়নি, ইচ্ছাকৃতভাবে। এই সুরক্ষা শুধু UI-তে না,
> Firebase Rules ও Cloud Function দিয়ে বলবৎ করা — প্রকাশিত ফলাফল লেখার একমাত্র
> রাস্তা Cloud Function (Admin SDK দিয়ে), কোনো ক্লায়েন্ট থেকে সরাসরি লেখার
> অনুমতিই নেই।

## ১০. নতুন সেশন যোগ করা

একই প্রক্রিয়া — সেশন তৈরি করুন, রোস্টার পেস্ট করে ইমপোর্ট করুন (PDF থেকে টেক্সট কপি
করে `SL REG NAME` ফরম্যাটে সাজিয়ে দিলেই হবে; প্রয়োজনে PDF/টেক্সট পাঠালে ফরম্যাট
করে দেওয়া সম্ভব), শিক্ষক ও ক্লাস যোগ করুন। প্রতিটি সেশনের ডাটা সম্পূর্ণ আলাদা থাকে —
একজন স্টুডেন্ট শুধু নিজের সেশনের তথ্যই দেখতে পাবেন।

## ১১. সমস্যা হলে যা প্রথমে চেক করবেন

কোনো ট্যাবে ডাটা "লোড হচ্ছে..." লেখায় আটকে থাকলে, বা কোনো এরর মেসেজ দেখালে, সাধারণত
এর একটার কারণে হয়:

1. **সর্বশেষ `database.rules.json` Publish করা হয়নি** — সবচেয়ে সাধারণ কারণ। নতুন
   ফিচার যোগ হলে প্রায়ই নতুন rules লাগে; পুরোনো rules থাকলে নতুন ডাটাবেজ পাথ পড়তে/লিখতে
   ব্যর্থ হয়। সমাধান: ধাপ ৪ আবার করুন।
2. **ইন্টারনেট সংযোগ** — সাধারণ কারণ, একবার রিফ্রেশ করে দেখুন।
3. **ব্রাউজার কনসোলে এরর দেখুন** — F12 চেপে Console ট্যাবে গেলে আসল এরর মেসেজ
   (যেমন "PERMISSION_DENIED") দেখা যাবে, যেটা কারণ বুঝতে সাহায্য করবে।

এখন থেকে অ্যাপের প্রতিটা তালিকা লোড হওয়ার জায়গায় এরর হলে স্পষ্ট মেসেজ দেখাবে (আগে
কিছু জায়গায় এরর হলে "লোড হচ্ছে..." স্ক্রিনেই আটকে থাকত, কোনো ব্যাখ্যা ছাড়াই — এটা
ঠিক করা হয়েছে)।
